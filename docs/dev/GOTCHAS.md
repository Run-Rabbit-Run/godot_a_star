# Ловушки Godot и Windows

Неочевидные проблемы, на которые уже уходило время при работе со скриптами, тестами и правками файлов. Проверять список перед добавлением скриптов и тестов и перед скриптовыми правками. Новую ловушку записывать сюда в той же задаче, где её нашли.

## Godot 4.7

- **Новый `class_name` не виден в `--script`-прогонах**, пока не пересканирован глобальный кэш классов. `tools/tests/run_tests.py` делает это сам, если находит класс, отсутствующий в кэше; для отдельного `--script`-запуска один раз выполнить из корня проекта:

  ```powershell
  & Z:/Godot/Godot_v4.7-stable_win64_console.exe --headless --editor --quit --path .
  ```

  Ошибки GitPlugin о заблокированной DLL при этом запуске были и раньше и не мешают.

  Смену базового класса у существующего `class_name` (например, `Node` → `RefCounted`) раннер не замечает: кэш остаётся старым, и скрипты, которые используют этот класс, падают с «Could not find type …». Пересканировать кэш той же командой.
- **`Resource.duplicate(true)` не копирует внешние ресурсы** — те, что лежат отдельным файлом, в том числе внутри массивов и словарей. Копия держит тот же объект, что и кэш `ResourceLoader`, и правка «копии» меняет оригинал (так было с турелью в параметрах призыва и с юнитами пакета в `SkillLibrary.apply_to_packages()`). Внешние элементы копировать явно; в определениях правил ссылаться на контент по ID.
- **`ProjectSettings.get_setting()` не применяет переопределения по feature tag** вроде `.release` или `.windows`, их применяет только `get_setting_with_override()`. Флаги, которые должны меняться в зависимости от сборки, читать вторым способом. Проверено на Godot 4.7: `flag.debug=false` в debug-запуске через `get_setting` даёт `true`.
- **Нельзя называть `class_name` так же, как нативный класс редактора** (например, `EditorInspector`): побеждает нативный класс, и члены не находятся с ошибкой «Cannot find member». Поэтому панель редактора поля называется `BattleEditorInspector`.
- **`LineEdit.text_changed` от настоящего ввода приходит в конце кадра.** Тест, отправляющий `InputEventKey`, должен выполнить `await process_frame` перед проверкой документа.
- **`BaseButton.set_pressed_no_signal(true)` не отжимает остальные кнопки `ButtonGroup`.** Состояние каждой кнопки задавать явно.
- **Ошибка во время выполнения функции не возвращает `null`.** Вызывающий код получает значение по умолчанию для объявленного типа: для `-> Array[BattleEvent]` это пустой список, и сбой неотличим от «нет событий». Узнать об ошибке можно только подпиской `Logger` через `OS.add_logger()`: ошибки GDScript приходят с `ERROR_TYPE_SCRIPT` на том же потоке (см. `features/abilities/script_error_watch.gd`).
- **Список логгеров `OS.add_logger()` / `OS.remove_logger()` не защищён мьютексом.** Добавление или удаление логгера на рабочем потоке, пока другой поток пишет в лог, — гонка в самом движке. Логгер устанавливать один раз на главном потоке и не снимать; счёт ошибок по потокам вести внутри него под `Mutex` (так сделан `ScriptErrorWatch`).
- **`освобождённый_объект as Тип` — ошибка скрипта, а не `null`** («Trying to cast a freed object»). Сначала проверять `is_instance_valid()` на значении типа `Variant`, потом приводить.
- **Тест не может намеренно вызвать ошибку скрипта в обычном наборе**: `run_tests.py` валит набор на любой `SCRIPT ERROR`. Для такой проверки нужен отдельный прогон с перечнем ожидаемых строк ошибок и их точным числом (как `features/battle/tests/handler_crash_check.gd`).
- **Headless-прогон не делает скриншоты.** Для рендера UI нужен оконный `--script`-запуск и `root.get_texture().get_image()`. Вспомогательные скрипты класть в игнорируемый `build/` и удалять после проверки.
- **Порядок загрузки скриптов влияет на утечки при выходе.** Когда `BattleEditorShell` перестал делать `preload` сцены боя, `editor_smoke` начал завершаться с «ObjectDB instances were leaked» и «resources still in use»: утекали только скрипты `features/` (документ, snapshot, запрос боя), без узлов. Вернуть `preload` в редактор устранило утечку; поэтому редактор передаёт сцену `EditorTrialRunner`, а раннер регрессий заранее загружает `core_package.tres`. Если после переноса `preload` появилась такая утечка, сначала проверить порядок загрузки.
- **Новый PNG или SVG не загружается в `--script`-прогоне, пока редактор его не импортировал.** `preload` падает с ошибкой загрузки ресурса. Импорт выполняет та же команда `--headless --editor --quit`; она же создаёт `.import` рядом с файлом. Параметры импорта (`mipmaps/generate`, `svg/scale`) правятся в `.import` и вступают в силу после повторного запуска этой команды. У SVG по умолчанию нет mipmaps, и уменьшенный рисунок рябит.
- **`Array.sort()` упорядочивает `StringName` не по алфавиту.** Массив `[&"left", &"right"]` после `sort()` оказался `[&"right", &"left"]`. Для стабильного порядка сравнивать `String(a) < String(b)` в `sort_custom` (так делает `BattleEngine._is_unit_id_before`), а в тестах проверять состав через `has()` и `size()`.
- **`ResourceSaver.save` вне редактора не пишет `uid` в заголовок `.tres` и убирает уже записанный**; `ResourceSaver.set_uid` там тоже ничего не меняет. Поэтому `AtomicFileWriter.save_resource` через временный файл даёт тот же заголовок, что и прямое сохранение. Ссылаться на сохраняемые из инструментов ресурсы только по пути.

## Тесты редакторов

- Smoke-тесты обращаются к внутренностям редакторов по приватным именам через `editor.get("_name")`: `_terrain_id_edit`, `_side_option`, `_document`, `_confirm` и другие. При переносе виджетов в панели сохранять эти имена как поля-псевдонимы в shell, иначе падает `tools/battles/tests/editor_smoke.gd`.

## Окончания строк

Репозиторий хранит текст с LF (`.gitattributes`: `eol=lf`).

- Python `Path.write_text` на этой машине пишет CRLF: записывать байты либо после правки выполнить `sed -i 's/\r$//' <файл>`.
- Инструмент Edit агента тоже переводил целые файлы в CRLF (AGENTS.md и BATTLE.md, 2026-10-31). В Claude Code это исправляет хук `.claude/hooks/normalize_eol.py` после каждого Edit/Write внутри репозитория. Другим агентам и после скриптовых правок проверять вручную: `tr -cd '\r' < <файл> | wc -c` должно вывести 0.
- Рабочие копии части файлов лежат в CRLF, хотя в git хранятся с LF (`git ls-files --eol` показывает `w/crlf`). Git и Godot этого не замечают, но скриптовая замена по шаблону с `\n` не находит совпадений. Перед такой правкой привести файл к LF: `sed -i 's/\r$//' <файл>`.

## Инструменты агента

- Инструмент Bash схлопывает `\\` в `\` даже внутри heredoc в одинарных кавычках. JSON с путями Windows и строки GDScript с `\n` в скриптовой правке ломаются. Такие правки делать через Edit/Write либо собирать обратный слэш через `chr(92)`.
