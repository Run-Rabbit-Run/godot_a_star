# Редактор юнитов

Откройте `res://unit_editor.tscn` в Godot и нажмите F6. Либо запустите `features/editor/battle_editor.tscn` и нажмите «Редактор юнитов» в разделе расстановки справа.

1. Нажмите «Новый» или выберите ранее сохранённого юнита слева.
2. Задайте имя, изображение, ОЗ, базовый урон, тип атаки и очки передвижения.
3. У ближней атаки дальность всегда 1 гекс. Дальняя атака имеет дальность 2–20 гексов, включая возможность атаковать соседнюю клетку по общим правилам боя. На дорогих клетках очков передвижения хватает на меньшее число гексов.
4. Отметьте «Бросок гранаты» и/или пассивную «Боевую подготовку». Подготовка добавляет 3 к обычной атаке, не меняя базовый урон и урон гранаты. Итог показан под формой.
5. Нажмите «Сохранить». При возврате в редактор боя палитра и изображения расстановки обновляются. Карта, расстановка и история её правок сохраняются. Если редактор юнитов открыт отдельным процессом, нажмите в редакторе боя «Обновить библиотеку юнитов».

Слева находятся пользовательские юниты. Штатные определения пакетов `.tres` этот редактор не изменяет. «Создать копию» создаёт новый независимый ID; переименование сохраняет прежний ID и ссылки из боёв. «Отменить»/«Повторить» меняют текущий черновик; после отмены ранее сохранённой правки нужно сохранить заново.

## Папки

- `user://unit_library/units` — JSON-файлы юнитов, по одному на определение.
- `user://unit_library/assets` — изображения PNG, WebP, JPG/JPEG. При запуске сюда копируются отсутствующие стартовые изображения `0.png`–`7.png` из `res://features/battle/art/plateau_units`.
- Кнопки «Папка юнитов» и «Папка изображений» открывают фактические каталоги на компьютере. По умолчанию Windows это `%APPDATA%/Godot/app_userdata/a_star/unit_library`.

Добавьте изображение в assets и нажмите «Обновить списки». Предпочтительны PNG с прозрачным фоном и опорой у нижнего края. Изображение используется для фигуры и портрета, размер фигуры в бою — 82 единицы presentation. Для переноса библиотеки копируйте обе папки; JSON боевого документа хранит ссылки на ID, а не вложенные определения юнитов.

Сохранение использует временный файл и резервное переименование предыдущей версии. При ошибке операции редактор показывает причину и сохраняет открытый черновик. Ошибочный JSON не заменяет текущий черновик. Несохранённые правки защищены при смене юнита, создании нового и закрытии отдельного редактора кнопкой или системным закрытием окна.

После внешнего редактирования библиотеки повторная загрузка должна пройти полностью: повреждённый JSON или изображение блокирует обновление, предыдущий ContentSnapshot остаётся действующим. При первоначальной ошибке загрузки можно открыть папку из редактора юнитов, исправить файл и обновить библиотеку.

Проверены запуск обеих сцен без ошибок GDScript и статичный рендер формы. Интерактивные сохранение, загрузка, расстановка и пробный бой пока не подтверждены: computer-use не смог захватить окно (таймаут). Автоматические тесты не добавлялись и не запускались.
