# Редактор юнитов

Откройте `res://tools/units/unit_editor.tscn` в Godot и нажмите F6. Либо запустите `tools/battles/battle_editor.tscn` и нажмите «Редактор юнитов» в разделе расстановки справа.

1. Нажмите «Новый» или выберите ранее сохранённого юнита слева.
2. Задайте имя, изображение, ОЗ, уровни брони, базовый урон, тип атаки и очки передвижения.
3. У ближней атаки дальность всегда 1 гекс. Дальняя атака имеет дальность 2–20 гексов, включая возможность атаковать соседнюю клетку по общим правилам боя. На дорогих клетках очков передвижения хватает на меньшее число гексов.
4. Отметьте нужные активные умения: «Бросок гранаты», «Электрическое поле», «Разлить воду», «Огненное поле», «Разлить масло», «Разлить кислоту» и/или пассивную «Боевую подготовку». Подготовка добавляет 3 к обычной атаке, не меняя базовый урон и урон гранаты. Итог показан под формой.
5. Нажмите «Сохранить». При возврате в редактор боя палитра и изображения расстановки обновляются. Карта, расстановка и история её правок сохраняются. Если редактор юнитов открыт отдельным процессом, нажмите в редакторе боя «Обновить библиотеку юнитов».

Слева находятся авторские юниты проекта. Штатные определения пакетов `.tres` этот редактор не изменяет. «Создать копию» создаёт новый независимый ID; переименование сохраняет прежний ID и ссылки из боёв. «Отменить»/«Повторить» меняют текущий черновик; после отмены ранее сохранённой правки нужно сохранить заново.

## Папки

- `res://content/authored/units` — JSON-файлы юнитов, по одному на определение.
- `res://content/authored/assets/units` — изображения PNG, WebP, JPG/JPEG. Стартовые изображения уже находятся в проектной библиотеке.
- Кнопки «Папка юнитов» и «Папка изображений» открывают фактические каталоги на компьютере. Обе папки находятся внутри проекта `a_star`; AppData больше не используется.

Добавьте изображение в assets и нажмите «Обновить списки». Предпочтительны PNG с прозрачным фоном и опорой у нижнего края. Изображение используется для фигуры и портрета, размер фигуры в бою — 82 единицы presentation. При переносе проекта сохраняйте обе папки; JSON боевого документа хранит ссылки на ID, а не вложенные определения юнитов.

Сохранение использует временный файл и резервное переименование предыдущей версии. При ошибке операции редактор показывает причину и сохраняет открытый черновик. Ошибочный JSON не заменяет текущий черновик. Несохранённые правки защищены при смене юнита, создании нового и закрытии отдельного редактора кнопкой или системным закрытием окна.

После внешнего редактирования библиотеки повторная загрузка должна пройти полностью: повреждённый JSON или изображение блокирует обновление, предыдущий ContentSnapshot остаётся действующим. При первоначальной ошибке загрузки можно открыть папку из редактора юнитов, исправить файл и обновить библиотеку.

Проверены запуск обеих сцен без ошибок GDScript и статичный рендер формы. Интерактивные сохранение, загрузка, расстановка и пробный бой пока не подтверждены: computer-use не смог захватить окно (таймаут). Автоматические тесты не добавлялись и не запускались.

## Подключение к игре

Библиотеку читает общий `UnitLibrary` в `features/content/units/`. И редактор поля, и основной запуск игры объединяют её со штатными пакетами. Бой хранит ID юнитов; отдельного копирования определений в JSON боя не требуется. Сохраните библиотеку в Git вместе с изображениями. Общий workflow: [README.md](README.md).

Текущая граница проверки после переноса описана в [STATUS.md](../architecture/STATUS.md).


## Погибшие варианты и анимация смерти

Для всех20 изображений библиотеки добавлена погибшая пара. Положить тело в `content/authored/assets/corpses/` с тем же basename, что у живой картинки: например, `units/gt_engineer.png` и `corpses/gt_engineer.png`. Редактор показывает наличие пары; она автоматически подключается к существующим и новым юнитам при загрузке библиотеки. Документ юнита сохраняет прежний формат и ID. При отсутствии пары используется запасное изображение тела.

Размер задаётся в `content/authored/unit_visual_profiles.json`: `corpse_width` — видимая ширина, `corpse_visible_region` — измеренный прямоугольник заметного рисунка (alpha≥32/255). При отсутствии прямоугольника измеряются обычные alpha-bounds. У PNG тел включать mipmaps для читаемого уменьшения.

Для просмотра всех смертей запустить через F6 `tools/units/unit_death_preview.tscn`: живые фигуры стоят рядом с падающими, затем остаются тела. Можно повторить переход, сменить скорость и скрыть гексы. В самой игре используются те же акторы и аниматор. Правило создания живого/погибшего ассета: `docs/art/UNIT_ASSETS.md`.

## Состояния — 2026-10-04

Броня блокирует физический урон по числу уровней. Кислота разрушает броню; старые JSON без поля armor получают 0. Пять умений создания состояния действуют на существующие клетки в радиусе 1, дальность применения 3. Создавая разные состояния на одной клетке, можно получить сочетания из матрицы, взрывы и распространение на соседей. Эффекты юнита отображаются иконками с уровнями под HP; наведите мышь для описания. Полные правила и рабочие балансные допущения: [HEX_AND_UNIT_STATES.md](../architecture/HEX_AND_UNIT_STATES.md). Для ручного просмотра в обычном бою откройте features/battle/view/hex_status_preview.tscn (F6).
