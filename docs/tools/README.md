# Инструменты разработки A_star

Все редакторы находятся в `tools/`. Они запускаются отдельно через F6 в Godot и не входят в сборку игры.

| Инструмент | Сцена для F6 | Руководство | Данные |
| --- | --- | --- | --- |
| Юниты | `tools/units/unit_editor.tscn` | [UNITS.md](UNITS.md) | `content/authored/units`, изображения `content/authored/assets/units` |
| Поле боя | `tools/battles/battle_editor.tscn` | [BATTLES.md](BATTLES.md) | `content/authored/battles` |
| UI боя | `tools/battle_ui/battle_ui_editor.tscn` | [BATTLE_UI.md](BATTLE_UI.md) | `content/authored/ui`, изображения в `assets` внутри этой папки |

`res://` обозначает корень проекта с `project.godot`. Полные пути показываются после сохранения; редактор юнитов также умеет открывать обе папки в проводнике. Данные предназначены для Git вместе с кодом игры.

## Создать и запустить свой бой

1. Создай и сохрани определения юнитов. После отдельного процесса обнови библиотеку в редакторе поля.
2. Открой редактор поля. Он загружает текущий стартовый документ игры. Измени клетки, фон, состояния и расстановку.
3. Сохрани JSON в `content/authored/battles/`. Для другого боя используй «Сохранить как…».
4. Проверь документ и запусти «Пробный бой». Возвращение сохраняет авторский документ и не переносит в него урон или движения из боя.
5. Нажми «Сделать стартовым боем». Текущие правки сохраняются; документ и зависимости проверяются перед назначением.
6. Нажми F5: `features/game/game.tscn` прочитает выбранный документ и запустит общий `BattleScreen`.

Поле — документ с данными, а не отдельная Godot-сцена. Начальная карта и расстановка задаются JSON; сцена, правила и управление боем общие.

## Выбрать UI игры

Сохрани вариант в `content/authored/ui/` и нажми «Использовать в боях». «Вернуть стандартный UI» очищает выбор. Назначение действует при следующем запуске. Пробный бой UI использует текущий стартовый бой с копией несохранённого оформления.

## Конфигурация и перенос

`content/game_content.tres` хранит общий список `content_packages`, `battle_document_path` и `ui_profile_path`. Можно выбрать файлы через Inspector этого ресурса или через редакторы. Назначение из инструментов допускает только файлы внутри `content/`, чтобы оно переносилось вместе с проектом. Пустой `ui_profile_path` означает стандартный HUD.

Бой содержит ссылки на определения юнитов по стабильным ID. При переносе нужны весь проект либо соответствующий комплект JSON и изображений; один JSON боя не включает библиотеку юнитов. Загрузчик проверяет версии пакетов и определения до запуска. Повреждённый обязательный контент блокирует запуск с сообщением.

При миграции 2026-10-03 семь определений и 20 изображений скопированы из AppData в проект; ID и содержимое сохранены. `first_custom_battle.json` перенесён из `battle_templates/` и выбран стартовым. Оригинальная библиотека в AppData оставлена как резервная копия и больше не используется игрой или редакторами. Настройки окна и будущие сохранения прохождения остаются в `user://`. Диагностические логи боя сохраняются в `logs/battles` в папке игры; включение и формат: [BATTLE_FILE_LOGGING.md](BATTLE_FILE_LOGGING.md).

## Экспорт

Профиль `Windows Game` в `export_presets.cfg` включает ресурсы игры и JSON из `content/authored/`, исключает `tools/`, документацию, существующие тестовые сценарии и вспомогательный экспорт редактора. Обработчики общих документов находятся в `features/content/` и остаются в сборке. Папка `build/` исключена из Git.

Для исполняемого Windows-файла нужны шаблоны экспорта Godot 4.7. PCK можно собрать без них: `--headless --path <проект> --export-pack "Windows Game" build/a_star.pck`.

«Экспорт» внутри редактора поля создаёт `content/authored/exports/<ID боя>/manifest.json` и `battle_document.json`. Это вспомогательная копия документа, не самодостаточный мод и не способ назначения стартового боя. Общий внешний загрузчик модов не реализован.

Архитектурные контракты: [EDITOR.md](../architecture/EDITOR.md), [CONTENT_AND_MODS.md](../architecture/CONTENT_AND_MODS.md).
