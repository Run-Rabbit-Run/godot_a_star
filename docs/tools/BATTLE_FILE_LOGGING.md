# Запись диагностического лога боя

## Включение

В `project.godot` включить флаг и перезапустить игру:

```ini
[feature_flags]
battle_file_logging=true
```

По умолчанию флаг выключен: подсистема не создаётся, переключатель отсутствует, сохранённое предпочтение не применяется. Экспортировать игру нужно с включённым флагом, если диагностика нужна в сборке.

В бою открыть настройки (шестерёнка), включить **«ЗАПИСЫВАТЬ ЛОГ БОЯ В ФАЙЛ»**. Переключатель доступен во время AI, анимации и после результата. Предпочтение хранится в `user://battle_logging.cfg`: следующие бои записываются автоматически с начала. Ошибки открытия/записи показываются в настройках; ошибка необязательной диагностики отключает запись и не останавливает бой.

## Файлы

- Сборка: `<папка exe>/logs/battles/`.
- Запуск проекта через Godot: `<корень проекта>/logs/battles/`.
- UTF-8 JSONL: один JSON-объект на строку, уникальный файл на непрерывный сегмент записи.
- Имя содержит UTC-время, PID и счётчик времени процесса. Существующие файлы не перезаписываются.
- Полный путь к текущему/последнему файлу показан в подсказке строки статуса.
- Логи исключены из Git и экспорта. Автоматической ротации и удаления нет.

Выключение завершает сегмент; повторное включение создаёт новый файл. `coverage=from_current_state` означает отсутствие действий до включения; первым записывается текущий полный снимок. Автоматическая запись с начала содержит `coverage=battle_start`, входные данные и начальную `BattleResolution`, включая стартовые реакции гексов и пропуски ходов. Снимок заголовка уже отражает рассчитанные начальные эффекты; исходные данные находятся в `setup`.

## Схема версии 1

Для обречённого AI дополнительно сохраняется `trace.last_action`: прогноз оставания, рассмотренные клетки, фактически достигнутая позиция, выживание после движения, доступные основные действия, прогноз фактического урона противникам/союзникам и выбранный план. Причины: `doomed_maximum_damage` — максимальный урон перед гибелью; `doomed_advance_toward_enemy` — сближение при отсутствии доступного урона; `doomed_no_reachable_progress` — продвижение недоступно. Прогноз учитывает текущий ход, а не будущие действия всех участников.

Каждая строка: `schema_version`, `sequence`, `utc`, `elapsed_usec`, `battle_id`, `seed`, `round`, `active_unit_id`, `state_revision`, `map_revision`, `kind`, `data`. Последовательность и монотонное время задают порядок внутри файла; UTC связывает запуски.

| kind | Данные |
| --- | --- |
| `recording_started` | Полнота записи, версия Godot, приложение, ContentLock, определение боя, эффективный BattleSetup со сторонами/профилями AI/спавнами, определения юнитов/способностей/рас, текущий снимок |
| `initial_resolution` | Начальные события, ревизия, результат, terminal_error |
| `command_requested` | Тип и все поля команды, управление активным юнитом, снимок до исполнения; также null/недопустимые команды |
| `resolution` | Принятие/отказ и причина, terminal_error, упорядоченные события со всеми полями, результат, снимок после исполнения |
| `ai_decision` | Источник, профиль, команда, контекст и диагностический след выбора |
| `map_mutations_requested` | Внешние мутации и снимок до применения |
| `control_source_changed` | Смена источника команд стороны, тип, автоматический режим, профиль |
| `recording_stopped` | Причина, описание ошибки, финальный снимок, BattleResult (если есть), счётчики и аналитика |

Снимок содержит всех юнитов, включая погибших: позиции, HP, движение и основное действие, параметры атаки и тип урона, иммунитеты, статусы, активные/пассивные способности, статусы обычной атаки, число начатых собственных ходов, режимы/дальность/радиусы целей и cooldown. Карта содержит каждый существующий гекс, terrain/state ID, проходимость и стоимость движения. Также сохраняются очередь, активный юнит, раунд, ревизии, исход, описание цели и состояние RNG строкой без потери точности большого целого.

События урона содержат фактический, базовый и рассчитанный урон, упорядоченные модификаторы с ID источников, тип урона, атакующего/цель, источники способности/гекса/статуса, оставшиеся HP и гибель. Остальные события сохраняют публичные поля: движение, завершение хода, способности, статусы, призыв и мутации карты.

След встроенного AI содержит причину выбора, противников, цель сближения, допустимые цели атаки, союзников и проверенные способности с допустимыми гексами/КД/радиусом/режимом и оценками целей. Для движения: оценка оставания, использование путей до позиции атаки, вес урона, каждый проверенный кандидат, маршрут, стоимость, прогноз опасности, оценка, причины отклонения и выбранная клетка. Варианты записываются по фактическому порядку рассмотрения; после принятого решения алгоритм остальные варианты не исследует. Другие CommandSource сохраняют тип и команду, но собственный след должны предоставлять отдельно.

Аналитика: команды по типу, решения AI, принятые/отклонённые операции, события по типу, фактический урон по типу и источнику, количество погибших. Счётчики относятся только к записанному сегменту; начальные события учитываются при записи с начала.

Причины завершения: `battle_finished`, `battle_failed` (с описанием), `disabled`, `scene_closed`. Закрытие сцены не выдаётся за завершение боя. Внезапное завершение процесса может оставить файл без footer; каждая строка сразу сбрасывается на диск. Для повреждённого файла анализировать полный валидный префикс строк. Подробные снимки/прогнозы увеличивают время шага; боевой RNG и выбор действий от записи не меняются.

Это журнал диагностики, а не готовый формат save/replay. Внутренние этапы механик, не представленные событиями/снимками, и произвольный внутренний код модов не трассируются. Текстовый «Боевой лог» HUD работает независимо.
