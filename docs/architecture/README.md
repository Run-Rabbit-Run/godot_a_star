# Каноническая архитектура A_star

## Статус документа

Это основной источник архитектурных решений для Godot-проекта A_star. Архитектурные заметки из внешнего Obsidian-хранилища больше не требуются для разработки проекта.

Документ описывает обязательные границы. Текущее покрытие и незавершённые части перечислены в [STATUS.md](STATUS.md).

## Основное решение

A_star — модульный монолит на Godot 4.7:

- одно приложение и один репозиторий;
- независимое от сцены ядро пошагового боя;
- один проверенный `ContentSnapshot` для игры, редактора и симуляции;
- отдельное изменяемое состояние каждого запуска;
- графическая игра, пользовательский редактор и headless-симулятор являются адаптерами общего ядра;
- новые варианты контента создаются композицией данных, а не ветвями наследования юнитов.

ECS, микросервисы, глобальный EventBus и отдельный движок симуляции не вводятся без измеренной необходимости.

## Направление зависимостей

```text
content/ и определения
        ↓
ContentLoader → ContentSnapshot
        ↓
BattleStartRequest → BattleSetupFactory → BattleSessionFactory
        ↓
BattleSession → BattleEngine → BattleState
        ↓
BattleResolution / BattleResult / read-only снимки
        ↓
графический адаптер | редактор | симулятор | кампания
```

Внешний слой может зависеть от внутреннего. Ядро боя не зависит от сцены, UI, файлов, редактора или анимации.

## Базовые типы Godot

- `Node` используется для сцены, ввода, UI, звука, визуала и жизненного цикла приложения.
- `Resource` используется для общих определений и удобного внутреннего авторинга.
- `RefCounted` и обычные классы используются для правил, сессий, снимков и изменяемого runtime-состояния.

Использование `Vector2i`, `RandomNumberGenerator` и других обычных типов Godot не нарушает независимость ядра от `SceneTree`.

## Нерушимые правила

1. `BattleEngine` — единственный исполнитель боевых правил и владелец изменений `BattleState`.
2. UI, `UnitActor`, `BattleMapView` и анимации не меняют здоровье, позицию, очередь ходов или исход.
3. Игрок и ИИ отправляют одинаковые `BattleCommand` через `BattleSession`.
4. Графический слой получает снимки и события, а не изменяемые `UnitState`.
5. `BattleScreen` принимает `BattleStartRequest` и возвращает `BattleResult`; кампанию он не изменяет.
6. `ContentSnapshot` фиксируется на время запуска. Контент не подменяется посреди боя.
7. `BackgroundLayer` — только визуальная подложка. Существование клетки задаёт `BattleMapDefinition`/`HexGrid`.
8. Скорость воспроизведения меняет только длительность показа.
9. Редактор изменяет `EditorDocument` через `EditCommand`; пробный бой не записывает runtime-состояние обратно.
10. Любой автоматический цикл имеет лимит и структурированный результат.

## Декомпозиция

Каждый модуль и файл должен объясняться одной фразой без «и ещё». Размер 2 000 строк — аварийный потолок, но разделение выполняется раньше, если части имеют разные причины изменения.

Новая граница нужна, когда часть можно независимо:

- заменить;
- проверить;
- отключить;
- переписать;
- удалить без изменения соседних правил.

Координатор может знать несколько подсистем, но не должен содержать их правила, файловый ввод-вывод и конкретную отрисовку одновременно.

## Ошибки и degraded mode

- Ошибка обязательного определения, карты, расстановки, цели или правила блокирует запуск либо завершает текущую операцию.
- Частично созданный бой недопустим.
- Необязательный визуал может деградировать локально: отсутствующий VFX пропускается, изображение заменяется fallback, необязательный звук отключается.
- Fallback не меняет расчёт боя и не подменяет обязательный контент.
- Ошибка после возможного повреждения авторитетного состояния не скрывается продолжением игры.

## Feature flags

Feature flag создаётся только после явного согласия владельца проекта.

Если флаг кажется полезным, но его не просили, сначала нужно сообщить:

- какую функцию предлагается переключать;
- зачем нужен флаг;
- какое значение будет по умолчанию;
- когда и как временный флаг будет удалён.

Реализация начинается только после согласия. Одобренный флаг проверяется в точке композиции или запуска подсистемы, а не внутри правил боя.
