## Актуальные ограничения и долги

- `HexStateCatalog` пока остаётся встроенным каталогом. Перенос в content packages и выбор формулы совмещения стоимости местности/состояния не выполнены; текущие числа и правила стоимости сохранены.
- `BattleMapAssembler` больше не используется основным debug-запуском и остаётся legacy-адаптером. Новые зависимости на него не добавляются; удаление требует отдельной проверки миграционных сценариев.
- `BattleController` остаётся крупным графическим координатором выбора действия и AI presentation-loop. Правила в нём не размещать; выделять новый контроллер только при появлении отдельной причины изменения.
- `BattleEditorShell` объединяет сборку UI и workflow. Файловые сервисы, renderers и новые доменные правила следует выносить, а не наращивать shell.
- `UnitPresentationDefinition` и `AbilityPresentationDefinition` входят в общий `ContentSnapshot`, но логика боя их не читает. Headless-запуск обязан оставаться корректным без использования графических ресурсов.
- Политика ИИ `basic_melee` выбирает цель по прямому расстоянию и оценивает только ближайший ход. Опасные гексы за пределами этого хода, дальность способностей при сближении и групповая тактика не учитываются.
- `ContentLoader` работает с доверенными Godot `Resource`; это не безопасный data-only загрузчик внешних архивов.
- Текущий порядок ходов формируется порядком расстановок. Инициатива ещё не моделируется.
- Удаление гекса с живым юнитом и превращение его в непроходимый отклоняются; погибшие не блокируют мутации.
- Сохранение посреди боя не принято как требование.

## Ближайшие архитектурные направления

Порядок определяется конкретной следующей фичей, но безопасные границы такие:

1. Для внешних модов — import/migration/validation конвейер поверх текущего `ContentSnapshot`.
2. Для развития редактора — расширять `EditorDocument` и `EditCommand`, не хранить данные только в UI-нодах.
3. Для кампании — отделить постоянное `CampaignSession` от определений и добавить SaveService с ContentLock.
4. Для глубины боя — вводить runtime-состояния способностей/статусов в ядре, не в `UnitActor`.
5. Для балансировки — добавить batch-runner и отчёты поверх одного `SimulationRunner`.
6. Для skip/pause — определить отменяемый контракт presentation до добавления кнопки.
