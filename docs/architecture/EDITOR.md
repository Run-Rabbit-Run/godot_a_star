# Архитектура пользовательского редактора

## Отдельный редактор юнитов (2026-10-01)

`res://unit_editor.tscn` / `UnitEditor` редактирует отдельный JSON-черновик определения юнита; UI является проекцией словаря документа, изменения имеют undo/redo до 100 снимков. Этот документ не является расстановкой и не изменяет `EditorDocument` боя. Новый ID генерируется один раз; редактирование сохраняет ID, копирование создаёт другой. Смена документа проверяет несохранённые правки.

`UnitLibrary` отвечает за папки, структурную валидацию, чтение/сохранение и перевод JSON в `ContentPackage` с namespace `custom_units` и зависимостью `core`. `UnitDefinition` и `UnitPresentationDefinition` создаются раздельно; затем библиотека вместе с базовыми пакетами проходит обычный `ContentLoader` и создаёт общий `ContentSnapshot`. Ошибка любого файла блокирует обновление целиком. Существующий снимок не изменяется.

`BattleEditorShell` открывает редактор юнитов как отдельную дочернюю сцену, скрывая оболочку боя. На возврате перечитывает библиотеку и перерисовывает палитру и маркеры без замены документа карты и его истории. В самостоятельном запуске редактора юнитов обновление в другом процессе выполняется кнопкой. Пробный бой получает последний успешно загруженный снимок.

Библиотека: `user://unit_library/units/*.json`, изображения: `user://unit_library/assets`. Обязательны версия схемы 1, стабильный ID, имя, изображение, ОЗ, урон, тип/дальность атаки, передвижение и списки активных/пассивных умений. Файл называется по ID без namespace. Изображения ограничены файлами непосредственно в assets; исполняемые ресурсы не импортируются. Формат является узким локальным авторингом юнитов, а не импортом мод-пакета. Руководство: `docs/UNIT_EDITOR.md`.

## Цель

Автор без исходников игры создаёт бой: рисует поле, расставляет участников, назначает стороны и ИИ, проверяет документ, сохраняет его и запускает пробный бой.

Редактор использует те же определения и фабрики, что обычная игра. Копия боевых правил внутри редактора запрещена.

## Источник истины

`EditorDocument` — единственный авторитетный черновик боя. Он содержит:

- `document_id` и версию схемы;
- `BattleMapDefinition`;
- `BattleDefinition`;
- версии зависимых пакетов;
- метаданные редактора, не влияющие на правила.

`TileMapLayer`, маркеры, Inspector и UI-контролы только отображают документ. Они не являются форматом хранения.

Карта и расстановка изменяются как один документ. Удаление гекса может сделать размещение ошибочным; редактор не переносит и не удаляет юнита молча.

## Текущие компоненты

| Компонент | Ответственность |
| --- | --- |
| `BattleEditorShell` | Пользовательский workflow и композиция UI |
| `EditorBattleView` | Поле, маркеры, выбор, камера и инструменты мыши |
| `EditorDocument` | Целостный черновик и создание trial-request |
| `EditCommand` | Одно обратимое изменение документа |
| `EditorCommandHistory` | Undo/redo |
| `BattleAuthoringValidator` | Диагностика до запуска |
| `EditorDocumentSerializer` | JSON save/load |
| `EditorPackageExporter` | Экспорт manifest и документа |

`BattleEditorShell` является координатором. Новую файловую логику, правила боя или конкретный renderer не следует добавлять прямо в него; при росте они выносятся в отдельный сервис.

## Команды редактирования

Сейчас поддержаны:

- добавить, переместить, обновить, дублировать и удалить расстановку;
- добавить, обновить и удалить гекс.

Каждая команда хранит предыдущее состояние и поддерживает отмену. `EditCommand` не вызывает `BattleEngine`.

История удерживает не больше 100 отменяемых команд с полными снимками документа. При новой правке сверх лимита удаляется самый старый снимок; redo очищается. Переход на дельты и объединение мазка кисти остаются отдельными улучшениями.

`placement_id` — стабильный ID авторской расстановки. При запуске он преобразуется в уникальный runtime `unit_id`. Два экземпляра одного `definition_id` имеют разные `placement_id`.

## Визуальный workflow

Текущая пользовательская оболочка позволяет:

- видеть форму поля и все стартовые маркеры одновременно;
- искать юнитов в палитре;
- добавлять и перемещать юнитов на поле;
- выбирать сторону и override профиля ИИ;
- добавлять, удалять и настраивать гексы;
- выполнять undo/redo;
- валидировать документ;
- сохранять и открывать JSON;
- экспортировать пакет;
- запускать пробный графический бой.

Маркеры редактора не являются `UnitActor` и не создают `BattleState`.

## Валидация

Перед запуском проверяются как минимум:

- уникальность `placement_id`;
- существование определений юнитов, сторон и профилей ИИ;
- существование стартового гекса;
- отсутствие конфликтов занятости;
- корректность управления стороны и AI override;
- наличие обязательных участников и цели.

Черновик с ошибками можно сохранить. Ошибки блокируют пробный и обычный запуск; предупреждения не блокируют.

Неверные данные не исправляются молча.

## Пробный бой

```text
EditorDocument.duplicate_document()
→ validate(ContentSnapshot)
→ snapshot.with_battle_document(...)
→ BattleStartRequest
→ обычный BattleScreen или SimulationRunner
```

Пробный запуск включает несохранённые изменения. Возврат из боя не переносит здоровье, разрушенные клетки или другое runtime-состояние обратно в документ.

После завершения пробного боя экран результата остаётся открытым до нажатия «Вернуться в редактор»; при возврате итог (победа или поражение) попадает в строку статуса редактора. Ошибка запуска возвращает автора в редактор и показывает конкретную причину.

## Сохранение и экспорт

`EditorDocumentSerializer` сохраняет JSON со схемой документа и восстанавливает карту и бой.

`load_result()` возвращает документ либо `error_message` с ошибкой чтения, строкой ошибки JSON или путём некорректного поля. До создания ресурсов проверяются типы вложенных объектов, массивов и элементов, целочисленные значения, версия схемы и словарь версий пакетов. `load()` сохранён как совместимый API, возвращающий документ либо `null`. Структурная проверка не заменяет игровую валидацию черновика перед запуском; ошибочный файл не заменяет текущий документ.

`EditorPackageExporter` создаёт:

- `manifest.json`;
- `battle_document.json`.

Это экспортный формат редактора, но ещё не завершённый устанавливаемый мод: внешний import/load-контур для такого каталога пока не реализован. Внутренний `ContentLoader` работает с `ContentPackage : Resource`.

## Две возможные оболочки

Обязательная оболочка поставляется игрокам и уже представлена `battle_editor.tscn`.

В будущем допустим `GodotEditorAuthoringAdapter` для разработчика, но он должен использовать тот же `EditorDocument`, команды, валидатор и сериализатор. Отдельная модель данных для Inspector запрещена.

## Что ещё не реализовано

- авторинг целей, зон и сценарных триггеров через полный UI;
- редактор глобальной карты, диалогов и переходов кампании;
- установка экспортированного пакета через внешний загрузчик;
- полноценный Godot Editor plugin;
- визуальный список диагностики с переходом ко всем типам проблем;
- шаблоны карт и массовые операции.

Эти функции расширяют текущий документ и инструменты, но не меняют источник истины.

## Критерии

- После save/load совпадают гексы, расстановки, стороны, AI и модификаторы.
- Пробный бой использует ровно видимую форму поля и расстановку.
- Один документ проходит одинаковую валидацию в редакторе, игре и симуляции.
- Расстановка компьютерных противников выполняется без правки кода.
- Undo/redo не обходит `EditorDocument`.
- UI редактора не становится зависимостью ядра боя.

## Поле и палитра rim (2026-09-28)

Стартовый документ берётся из `plateau:battle`: все 216 гексов сетки 18×12 и демонстрационная расстановка. `EditorBattleView` использует геометрию образца: холст 1920×1080, гекс 94×78, центры (137 + 94·(q + r/2), 197 + 58,5·r). Масштабирование и панорама относятся только к виду.

- Нижняя `EditorStatePalette` показывает 12 состояний из общего `HexStateCatalog`; изображения берёт общий `HexStateArt`.
- ЛКМ и протягивание кисти наносят/стирают состояние через `EditCommand.update_hex`. Состояние заменяет предыдущее; стоимость движения берётся из каталога. Стирание оставляет гекс и возвращает стоимость 1.
- ПКМ стирает состояние; в режиме выбора/расстановки сначала удаляет находящегося на клетке юнита.
- Палитра юнитов содержит определения из `ContentSnapshot`, портреты и поиск. Повторные клики размещают выбранный тип; выбор существующего юнита и инструмент расстановки позволяют его перенести. Занятые и непроходимые клетки для расстановки отклоняются; копирование ищет ближайшую свободную клетку. IDs не пересекаются с загруженными расстановками.
- Удалённый гекс затемняется и отсутствует в `BattleMapDefinition.cells`; кисть добавления возвращает его. Новые клетки ограничены рамкой 18×12. Перед удалением занятого гекса UI требует переместить или удалить юнита.
- Фоны Аэр, Люмен и Умбра выбираются сверху. `EditCommand.set_background` меняет `map_definition.background_id`; undo/redo восстанавливает фон вместе с документом.
- Маркеры рисуют `actor_texture`, `actor_height` и `actor_foot_anchor` из presentation-определений, без создания `UnitActor` или боевого состояния. Отсутствующий визуал заменяется маркером.
- Сетка и фигуры скрываются независимо; это локальное состояние вида.

JSON схемы 1 расширен необязательными `map.background_id`, `map.presentation_frame` и `cells[].hex_state_id`. Старые документы открываются с фоном plateau, прежним вычислением рамки и пустыми состояниями. Новые сохраняют фон, состояния и фиксированную рамку. Экспорт пользуется тем же сериализатором.

`BattleScreen` передаёт presentation-поля карты в `BattleMapView`. Фиксированная рамка сохраняет положение оставшихся клеток относительно фона при удалении крайних гексов. Кнопка возврата завершает пробный просмотр без изменения документа.

Проверено: запуск редактора и основного боя в Godot 4.7 без ошибок, визуальный кадр редактора через Movie Maker. Автоматические тесты не добавлялись и не запускались. Интерактивный проход и save/load/trial через UI не подтверждены: захват окна computer-use дважды завершился таймаутом.

### Настройки окна редактора (2026-09-28)

`EditorDisplaySettings` вверху правой панели меняет размер текущего окна (720p–2160p) и полноэкранный режим без перезапуска процесса и изменения документа. В полноэкранном режиме используется размер монитора, выбранный размер окна применяется при возврате. Настройки не записываются в конфигурацию боя. Если окно встроено в Godot через `--wid`, элементы отключены с подсказкой отключить Embed Game on Play: размером такого окна управляет хост.

Масштабирование поля колёсиком удалено вместе с `_zoom_at`. Сохраняются автоматическое вписывание при изменении области, кнопка «По размеру окна» и панорама средней кнопкой. Прокрутка правой панели работает независимо.

Проверены загрузка/запуск сцены без ошибок и `git diff --check`. Автотесты не запускались; интерактивное переключение оконных режимов не проверено.

## Отдельный редактор UI боя (2026-10-01)

Точка входа `res://battle_ui_editor.tscn`, реализация в `features/editor/ui_layout/`. Это пользовательская оболочка в запущенной игре. Она не меняет EditorDocument карты: авторитетный документ presentation — `UILayoutDocument`, общий с runtime-потребителем HUD. Изменения выполняются через обратимые `UILayoutEditCommand`; история ограничена 100 командами. UI-ноды служат проекцией. Во время жеста изменяется отдельная preview-копия; отпускание мыши фиксирует одну команду, Escape отменяет жест.

Компоненты: `battle_ui_editor.gd` координирует workflow, `UILayoutCanvas` выводит настоящий HUD в SubViewport и обрабатывает мышь, `UILayoutInspector` выдаёт изменения формы, `UILayoutStore` выполняет файловые операции. Файловые диалоги не помещаются в ядро или документ.

Поддержаны дерево существующих блоков, перенос и восемь направлений resize, числовая геометрия, текст с `{value}`, шрифт, цвета/alpha, рамка, импорт изображений, видимость, reset, undo/redo, JSON save/load/save-as, назначение UI следующим боям и trial с копией несохранённого документа. Preview/zoom/панорама и раскрытие служебных панелей не сохраняются как изменения документа. При закрытии/открытии/создании другого документа проверяются несохранённые правки. Ошибка JSON не заменяет открытый документ.

Внешние изображения копируются в `user://battle_ui/assets` с именами по SHA-256 исходного файла. JSON содержит ссылки, поэтому перенос на другую машину требует также папки assets. Сохранение выполняется через временный файл и резервное переименование предыдущего. JSON проверяется до создания документа, допускается только известный набор свойств и ограниченные типы/размеры.

Пробный бой запускает обычный DebugBattleLauncher с `ui_document_override` и не записывает результат или локальное назначение UI. Руководство: `docs/BATTLE_UI_EDITOR.md`.


## Набор «Графичная тактика» (2026-10-02)

В списке изображений доступны 12 дополнительных PNG с префиксом `gt_`: officer, shield_guard, sniper, medic, heavy_gunner, engineer, mystic, small_stalker, large_mantis, spore_walker, alien_rifleman, gun_walker. Исходная папка: `res://features/battle/art/graphic_tactics_units/`. `UnitLibrary.ensure_folders()` копирует отсутствующие файлы в пользовательскую библиотеку при открытии редактора; существующие файлы не перезаписывает. Уже открытый редактор нужно перезапустить. Новые ресурсы включены явными preload-ссылками для экспорта. Игровые определения и назначенные изображения прежних юнитов не меняются.
