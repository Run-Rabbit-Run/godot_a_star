# Разделение крупных координаторов

**Статус:** в работе
**Начато:** 2026-11-01

## Цель

`BattleController` и `BattleEditorShell` координируют подсистемы, но не содержат их правил, файлового ввода-вывода и конкретной отрисовки (AGENTS.md «Декомпозиция»). Каждый выделенный модуль описывается одной фразой; поведение игры, редактора и все проверки не меняются.

## Не входит

- Новые возможности игры и редактора, изменение интерфейса.
- Изменение правил боя и формата документов.

## Затрагиваемые контракты

- `docs/architecture/BATTLE_PRESENTATION.md` «Компоненты»
- `docs/architecture/EDITOR.md` «Редактор поля»
- `docs/architecture/STATUS.md` «Ограничения и технический долг»

## Нужны решения владельца

Нет: разделение не меняет поведение.

## План

- [x] `BattleController`: выбор действия игрока (режим, выбранное умение, цели, поиск движения, подсветки, курсор, сборка команды по клику) → `PlayerActionSelection`.
- [x] `BattleController`: панель активного юнита и очередь ходов из снимков сессии → отдельный presenter HUD.
- [ ] `BattleEditorShell`: файловый workflow документа (новый, открыть, сохранить, сохранить как, библиотека боёв, назначение стартовым, экспорт, защита несохранённого) → отдельный модуль.
- [ ] `BattleEditorShell`: пробный бой (запуск, ошибка, возврат) → отдельный модуль.
- [ ] `BattleEditorShell`: операции карты (гексы, состояния, препятствия, расстановки) → отдельный модуль, если после предыдущих шагов shell остаётся смешанным.
- [ ] Обновить «Компоненты», «Редактор поля» и строки STATUS.md о размерах координаторов; удалить этот файл.

## Проверка

Полный `run_tests.py` после каждого шага; приватные точки входа, которыми пользуются тесты (`_on_hex_selected`, `_on_ability_requested`, `_select_hex`, `_replace_document`, `_start_trial` и др.), либо сохраняются, либо тесты переводятся на новые модули без ослабления. Ручная проверка мышью остаётся за владельцем.
