# Разработка по спецификации

Спецификация описывает ожидаемый результат конкретного изменения и наблюдаемые критерии приёмки. Создавайте её для новой функции, изменения игрового поведения или контракта. При исправлении бага с уже определённым поведением достаточно сценария воспроизведения, ожидаемого результата и регрессионного теста. Для чисто визуальной правки достаточно описания результата и проверки сцены.

Правила [уточнения задачи](../../AGENTS.md) применяются ко всем задачам.

## Порядок работы

1. После уточнения задачи создайте `<feature-slug>.md` по [шаблону](./_TEMPLATE.md). Запишите цель, границы, сценарии и наблюдаемые результаты. Используйте согласованные формулировки владельца и ссылки на действующие правила. Если при оформлении обнаружился пробел, уточните его до реализации.
2. Основывайте реализацию на согласованных критериях. Для многосессионной задачи ведите шаги, ход работы и передачу в [файле задачи](../tasks/_TEMPLATE.md). Если нужно изменить архитектурную границу или другой существенный контракт, оформите [ADR](../adr/README.md).
3. Проверьте каждый критерий автоматическим тестом или ручной проверкой и выполните требования проекта к проверке изменений. Связывайте критерии с конкретным сценарием, например «при повторной доставке результата этап кампании остаётся текущим». См. [AGENTS.md](../../AGENTS.md) «Проверка изменений».
4. При завершении сохраните спецификацию со статусом «реализована» и ссылками на профильные разделы. Она фиксирует требования, с которыми закрыли задачу. При изменении архитектурного контракта обновите профильный документ и [STATUS.md](../architecture/STATUS.md) в том же коммите. Правила закрытия временного файла задачи описаны в [AGENTS.md](../../AGENTS.md) «Файлы задач».
