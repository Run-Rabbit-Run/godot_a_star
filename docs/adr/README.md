# Архитектурные решения (ADR)

ADR фиксирует один существенный архитектурный выбор и его причину. Оформляйте его для изменений границ или зависимостей модулей, владельца состояния, общих интерфейсов, формата данных или гарантий совместимости. Текущие контракты описаны в [документах архитектуры](../architecture/README.md). При утверждении владельцем добавьте ссылку на ADR в [реестр решений](../DECISIONS.md).

## Порядок работы

1. Возьмите следующий свободный последовательный номер и создайте файл `NNNN-<slug>.md` по [шаблону](./_TEMPLATE.md). Номера сохраняются за записями.
2. Укажите статус `Proposed`. Опишите причины выбора, рассмотренные варианты, ожидаемые последствия и ссылку на связанную спецификацию, если она есть.
3. Согласуйте решение с владельцем до реализации. При согласовании укажите `Accepted`. При отклонении укажите `Rejected` и кратко запишите причину.
4. При замене принятого решения создайте новый ADR. Старую запись сохраните и поставьте ей статус `Superseded` со ссылкой на новую. Принятие решения и его реализация могут происходить в разные моменты. Текущее покрытие показывает [STATUS.md](../architecture/STATUS.md).

## Оглавление

Добавляйте сюда ссылку и статус при создании записи. При изменении статуса обновляйте его также в оглавлении.
