# A_star: инструкции по архитектуре и изменениям

## Назначение

Это Godot 4.7-проект с архитектурой модульного монолита. Ядро боя не зависит от сцены; графическая игра, пользовательский редактор, кампания и headless-симуляция используют общие правила и `ContentSnapshot`.

Внешняя Obsidian-папка `Архитектура/` не является источником истины. Каноническая архитектура хранится в этом репозитории.

## Точки входа

- `debug_battle_launcher.tscn` — графический debug-бой из content packages.
- `features/battle/battle_screen.tscn` — адаптер одного графического боя.
- `features/editor/battle_editor.tscn` — пользовательский редактор карты и расстановки.
- `features/campaign/debug_campaign_simulation_launcher.tscn` — headless-прогон кампании.
- `project.godot` — конфигурация; текущая main scene может быть отладочной.

## Направление зависимостей

```text
ContentPackage → ContentLoader → ContentSnapshot
→ BattleStartRequest → BattleSetupFactory → BattleSessionFactory
→ BattleSession → BattleEngine/BattleState
→ BattleResolution/BattleResult
→ controller/view | editor | simulation | campaign
```

Внешний слой может зависеть от внутреннего. Обратная зависимость запрещена.

## Обязательные границы

- `BattleEngine`, `BattleState`, `BattleSession` и `SimulationRunner` не зависят от `SceneTree`, `Node`, `PackedScene`, `Texture2D`, UI, ввода, Tween и файловых диалогов.
- `BattleEngine` единолично изменяет авторитетное состояние боя.
- Игрок и ИИ используют одинаковые `BattleCommand` через `BattleSession`.
- UI, `UnitActor`, `BattleMapView` и `PresentationQueue` только показывают снимки и события.
- `BattleScreen` принимает `BattleStartRequest`, возвращает `BattleResult` и не изменяет кампанию.
- `ContentSnapshot` — единый проверенный снимок контента для игры, редактора и симуляции.
- `UnitDefinition` хранит игровые данные и `presentation_id`. Сцены, текстуры, звук и визуальные параметры принадлежат presentation-определениям.
- `UnitState` создаётся без акторов. `UnitActorFactory` находится только на графической стороне.
- `BackgroundLayer` — только визуальная подложка. Существование клетки задают `BattleMapDefinition` и `HexGrid`.
- Отсутствующий гекс не равен существующему непроходимому гексу.
- Скорость воспроизведения никогда не меняет правила, RNG, число действий и `BattleResult`.
- Редактор меняет `EditorDocument` через `EditCommand`; UI-ноды не являются источником истины.
- Пробный бой использует snapshot документа и не записывает runtime-состояние обратно.
- Автоматические циклы имеют лимит, отмену и отдельный статус ошибки/ограничения.

## Ошибки и fallback

- Ошибка обязательных правил, карты, определения, расстановки, цели или зависимости останавливает запуск/операцию.
- Частично созданный бой недопустим.
- Degraded mode разрешён только для необязательной presentation: пропустить VFX, отключить звук, использовать placeholder/fallback actor.
- Fallback не меняет расчёт боя и не скрывает отсутствие обязательного контента.
- После возможного повреждения авторитетного состояния нельзя продолжать бой как будто ошибки не было.

## Feature flags

- Создавать feature flag только после явного согласия владельца проекта.
- Прямая просьба спрятать конкретную функцию является согласием только для этой функции.
- Если флаг кажется полезным, сначала сообщить: что он переключает, зачем нужен, значение по умолчанию и условие удаления. Дождаться согласия и только затем реализовывать.
- Не добавлять флаги «на всякий случай», для сокрытия ошибок или незавершённой обязательной логики.
- Одобренный флаг проверять в точке композиции/запуска подсистемы, а не размазывать по ядру.

## Декомпозиция

- Файл или модуль должен описываться одной фразой без «и ещё».
- 2 000 строк — аварийный потолок, а не целевой размер.
- Разделять по независимым причинам изменения, а не механически по количеству строк.
- Координатор может знать несколько подсистем, но не должен содержать их правила, файловый ввод-вывод и конкретную отрисовку.
- Не вводить интерфейс или слой без реальной сменяемой границы.

## Текущее состояние, которое нельзя путать с целью

- Внутренние `ContentPackage` реализованы как Godot `Resource`; внешний JSON/ZIP/PCK loader ещё не готов.
- Экспорт редактора ещё не образует полностью устанавливаемый мод.
- Кампания сейчас состоит из боевых сценариев; глобальная карта, база и SaveService ещё не реализованы.
- Статусы, cooldown, инициатива, batch-отчёты и универсальный skip presentation ещё не реализованы.
- Удаление занятого гекса и превращение его в непроходимый сейчас отклоняются.

Перед реализацией будущей возможности сверяться с `docs/architecture/STATUS.md`, а не предполагать её наличие.

## Проверка изменений

По умолчанию выполнить из корня проекта:

```powershell
git status --short -- .
git diff --check -- .
git diff -- .
```

Не добавлять и не запускать автоматические тесты без отдельного разрешения пользователя. Статические проверки не подтверждают runtime, интерактивный ввод, анимацию и визуальную читаемость; границы проверки указывать в отчёте.
